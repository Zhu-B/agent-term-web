# E 文件与存储

「覆盖丢了原件/并发写坏/路径换个工具不认」这一类.

---

### E1 覆盖改写前必须留底; "删除"= 挪走不真删

- 家法(全项目通用): 任何覆盖写旧内容前先留 `.bak`/旁路另存; 需要"删"的东西挪到
  隔离目录(如 `trash/`、`purged/`), 永不真删 —— 出事能捞回来.
- 配套: 版本库/回滚类功能"只覆盖永不删除", 删过的号不回收(防名字撞车).
- 出处: agent-term 家法(M12a 起, 2026-10-12/13 多起).

### E2 Windows 文件被占用时 os.replace 会静默失败 → 丢原件

- 现象: "写卡轮转"后原文件没了、新文件没写上(两端皆空).
- 根因: 目标文件被杀毒/编辑器/另一进程占着, `os.replace` 抛错被吞 or 静默不落地.
- 判据: 复现=对打开着的文件做 replace; 事后看两侧都不存在.
- 对策: 关键写路径改"**写临时文件 → 校验 → 拷贝兜底**"(拷贝失败还有原文件);
  或先检测占用, 失败时留底并明示用户.
- 出处: agent-term 记忆卡轮转(2026-10-13, 实锤丢原件后恢复).

### E3 mtime 会骗人 → 内容 sha1 做乐观锁

- 现象: 并发写"谁覆盖了谁"查不出来; 判"变没变"用 mtime 不可靠(同秒/回拨/拷贝保留).
- 对策: 变更检测看**内容 sha1**; 并发写=写锁 + 内容 sha1 乐观锁(读时记 sha, 写前核对,
  不符则弹确认/重读).
- 出处: agent-term 记忆卡覆盖治理(2026-10-13, mtime 会骗人实锤).

### E4 同一路径, 不同工具要不同形状

- 三种书写形态: bash/Git Bash 要正斜杠 `C:/x/` 或 `/c/x/`; WinRT/存储 API 只认反斜杠;
  JSON/jsonl 里是转义双反斜杠 `C:\\x`.
- 对策: 跨层传递路径时**在进门口归一**(`os.path.abspath` / `GetFullPath`), 别假设下游跟你
  一样宽容; 测试归一化要覆盖三变体(见 C4), 排查 B3.
- 出处: agent-term 家法 + wechat-eye(2026-10-10/13).
