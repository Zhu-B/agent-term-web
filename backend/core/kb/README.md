# 问题库 (kb) — 故障分类速查

agent-term 开发与使用中踩过的坑, 按类型归档: 症状 → 根因 → 判据 → 对策.
每条都带出处(文件/日期), 全部去重 —— 同一根因只在一个条目里讲透, 别处只交叉引用.

**怎么用(agent)**: 遇到报错/怪现象,**先按症状关键词在下表"速查索引"里找**;
命中 → 打开对应类型文件看条目对策; 没命中再从头查病灶.
修好后按文末「扩充协议」顺手沉淀 —— 下次的你和别人能省一趟.

**与记忆卡的分工**: 本库 = 通用技术故障手册(随软件走, 人人可用, 可改可扩展);
记忆卡 = 用户偏好/项目背景(跨会话个人记忆). 一次性任务细节和用户口味归记忆卡, 不进本库.

**与版本回滚的关系**: 本库不随「客制化与回滚」的版本快照(快照只收仓库根一层) ——
回滚软件不会把知识滚掉; 本库的改动保护靠 git(随仓库一起提交).

## 扩充协议(agent 自行沉淀, 不用问用户)

1. **命中症状但库里没有** → 修好后补一条. 格式: `### <编号> <一句话症状标题>` +
   现象 / 根因 / 判据(怎么快速确认是它) / 对策 / 出处(文件:行 + 日期).
   标题和判据里要放**可被搜到的关键词**(报错原文、现象词).
2. **放对位置**: 追加到对应类型文件末尾, 编号取该类型下一个号; 同时在上面
   速查索引补一行"关键词 → 编号", 并更新类型目录号段.
3. **已有同类条目** → 就地补充那条(加一行"追加(日期): …"), 不新开重复条目.
4. **只收跨任务复用的通用技术坑**. 一次性任务细节、用户偏好、项目背景 → 记忆卡.
5. **写错了/过时了** → 就地改正并标注日期, 不删旧条目假装没发生.
6. 条目要短: 能一眼扫完. 长篇分析放引用文件里, 这里只留结论与判据.
