# G 工程习惯与惯例

排查方法论与项目级惯例. 与 C(测试)类互为表里.

---

### G1 配置来源优先级: env > 本地文件 > 默认 —— "没配置却能用"先查环境残留

- 现象: 用户说"压根没配这个 key", 功能却能用(或别人机器上莫名多出一个可调用模型).
- 根因: 进程环境变量里有余留(旧实验/别的 CLI 留下的 export 写进了 shell 配置).
- 判据/自查: `echo $XXX_API_KEY` / `ls ~/providers.json` / 配置页看来源徽标(env/本地).
- 对策(排查): 用 C9 沙箱复现法证明代码干净, 再让用户查 shell 配置删残留;
  设计时**明确来源优先级并让 UI 显示来源**.
- 出处: agent-term qwen 之谜(2026-10-13).

### G2 改"软件自身"必须走客制化页(带防线的入口), 聊天窗是裸三键框

- 现象: 受保护文件(核心机制)被 agent 改掉并入档 —— 明明有防线.
- 根因: 那一轮是从**聊天窗**跑的(mode=frontend, 没有客制化水印与保护名单知识),
  权限门只是逐次弹三键框, 用户一路点允许 → 就改掉了.
- 对策: **入口决定防线** —— 改仓库走客制化页(提示词约束块 + 受保护硬拒 + 收工 sha1
  自动还原); 聊天窗只适合普通任务. 教训固化为项目惯例.
- 出处: agent-term 客制化拆页考古(2026-10-13).

### G3 bat 交付件两坑: if 块裸括号 / 非 GBK 字符

- `if not exist X (` 多行块里任何一句出现裸 `)`(如英文括号注释)会提前闭合块,
  **条件为假时整个 bat 也什么都不执行**(双击只见 pause 效果). 稳妥写法:
  `if not exist X goto label` + 文末 `:label`, 彻底不写括号块.
- 非 GBK 字符(⚠ ✓ ✗)输出重定向时按 cp936 崩 → bat 里 `set PYTHONIOENCODING=utf-8`
  (机制见 B1).
- 出处: stock 打包(2026-09-24), windows-bat-gotchas 记忆.

### G4 "别名/口口相传"的入口描述先对代码验证

- 实例: README 长期写着"双击 start.bat 开图形界面", 实际它自 M0 起就是**终端 REPL** 启动器;
  真 GUI 入口是后补的 start-gui.bat.
- 对策: 对外宣称的启动方式/路径, 以**代码与实测**为准; 发现讹传当场改文档并补正确入口.
- 出处: agent-term README 重排(2026-10-13).

### G5 修 bug 先立"修复前必红"的锚

- 习惯: 定位到根因后, 先在回归网里写一条**修复前必红**的断言(真点对话框/查
  winfo_ismapped/裸环境跑), 修复使其转绿 —— 这条锚永久防回归.
- 搭子: C8(探针法)确认病灶; 锚的写法参考 C2(走真实路径).
- 出处: agent-term 惯例(2026-10-12/13 多起: 建版对话框、A1、C1).

### G6 遍历线上格式前先打一份真实样例

- 现象: 按记忆里的形状写遍历/审计脚本(如 `t["name"]` 取工具名), 跑起来全空或全
  False —— 真格式其实是嵌套的(`{"type":"function","function":{"name":...}}`).
- 根因: 凭印象写结构假设, 没先看一条真实数据; 规范形与 wire 形还常常不是一回事.
- 判据: 打印一整个最小样本, 字段路径跟脚本里的取法对不上.
- 对策: **动手写遍历前先 print 一条真实样本**(或最小 fixture), 让脚本跟着样本走;
  取嵌套字段用形面自适应写法(`(t.get("function") or {}).get("name")`).
- 出处: agent-term M22 golden 审计脚本 `t["name"]` 全 None(2026-10-15), 取样后
  才见名字在 function.name.

### G7 第三方库集成"注册对但零反应": 先查根对象是不是库自己造的

- 现象: 集成第三方库(如 tkinterdnd2 拖拽): `drop_target_register`/事件绑定调用
  全不报错, 但事件**永不触发** —— 注册代码挑不出毛病.
- 根因: 库要求**根对象由它自己的构造器创建**(如 `TkinterDnD.Tk()`), 拿普通
  `tk.Tk()` 当根, 注册与绑定会被静默吞掉 —— 没有异常, 只有零反应.
- 判据/自查: 冒烟里同时断言"根具备库能力"(`hasattr(root, "drop_target_register")`)
  与"绑定真的挂上"(`widget.bind("<<Drop>>")` 非空) —— 只测其一测不出这类病.
- 对策: 根对象按库要求创建; 库缺失时降级路径也要冒烟(构造不炸); 事件类集成
  必须留一条"真事件触发过"的锚, 注册成功≠回调会来.
- 出处: agent-term M31 真拖拽(2026-10-15), 普通根吞掉 dnd_bind 实测.
