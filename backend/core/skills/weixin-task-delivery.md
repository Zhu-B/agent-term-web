# 微信任务 → 开发 → 交付 标准流程

用户(及其同事/上司)通过微信派任务, 交付物由用户微信转发。标准三段式:

## a 扫微信

- 用户说"看看微信有什么新任务"之类 → 用 MCP 的微信工具(wechat-eye: 截图 + OCR)取微信内容。
- OCR 输出是碎片, 用视觉档模型的 analyze_image(吃截图)修复成句; 提炼任务要点汇报, 和用户确认后再开工。
- 任务含糊(范围/规格/交付形式不明)用 ask_user 给 2~4 个选项问, 别默认替他决定。

## b 开发

- 每任务独立目录(如 `C:\Users\10601\<任务名>\`), 别混在 agent-term 或别的项目里。
- 按研究级标准稳做: 事实用工具核实、测完再交, 不赶工、不做保底糊弄版。
- 多步任务用 todo 列清单, 边做边更新。

## c 交付 —— 按类型二分

- **程序类**(可执行交付物): 打包成 zip **直接放桌面**, 文件名带版本号(如 `桌面工作台_v3.zip`); **出新版删旧版**, 桌面上只留最新一个 zip。
- **其它**(文档/清单/表格等不打包的): 在**桌面建任务名文件夹**放交付物, 后续更新迭代都进这个文件夹。
- 发出前版本必须已验证(测过/跑过绿); 同事反馈回来 → 在源码目录修 → 重新打包升版本号 → 删旧 zip。

## 规矩

- 最终回答用中文, 简洁直接; 引用文件路径一律正斜杠。
- 交付动作(往桌面写文件)做完向用户报一句放哪了、版本号多少。
